**Decision:** store `amount_cents` on `fine` instead of calculating it from the library's current rate every time.
 
**Why:** the amount is derivable (days overdue × daily rate), but the rate can change. If the council raises the fee, fines already issued must keep the amount that applied when they were issued. This is the "history" case: like a parcel keeping the address it was sent to.
 
**Cost and how it stays correct:** the value is written once, when the fine is issued, and never recalculated. The only way it changes is a deliberate correction (for example a waived fine), which is done by updating that row explicitly.
 
**What I would not denormalise:** a `copies_available` counter on `book`. The catalogue can compute it from `copy` and `loan` (copies with no open loan), and a stored counter would have to be updated on every loan and return, a likely source of update anomalies, with no proven speed problem at the scale of a municipal library.
